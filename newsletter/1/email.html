Roundtable-1 Roundup

RT-1 — the India Mobility Forum roundtable in session.

Roundtable-1 convened transit planners, academics, operators and builders to discuss opening up India's public-transport data. The conversation covered what's working, what's broken, and what needs to happen next.

Key outcomes

Consensus: open data and open systems are essential for public transport in India — proven in Delhi and via Namma Yatri.

Barriers: data locked in proprietary vendor systems, unwillingness to share, poor data quality (60% of project time), weak institutional capacity.

What's needed: national policy mandates, capacity building for agencies, standardized procurement, open-source platform adoption.

Where the discussion converged

No formal votes — what follows is where the room converged rather than binding decisions.

Public ownership of transit dataTaxpayer-funded data should be publicly owned — monetization models can still exist on top.
Open systems over proprietaryBuild on open-source platforms to avoid vendor lock-in and enable third-party innovation.
Data exchange architectureUse data exchanges as an intermediate layer to separate data from applications.

What's working

✓ Platforms exist: IUDX and Transport Stack are built and proven functional.
✓ Expertise available: IISc, IIIT Delhi, IIT Kanpur — on both technology and policy.
✓ Success cases: Transport for All challenge — startups built solid solutions on limited data.
✓ Government interest: MoHUA and Smart City Mission engaged.

What's not working

✗ Data locked in vendor systems: no incentive to open up; takes years to force.
✗ Unwillingness to share: cities fear exposing service gaps.
✗ Poor data quality: 60% of project time fixing it; 37% of trips break route IDs.
✗ No data SLAs: feeds shut off arbitrarily despite heavy citizen use.
✗ Privacy paralysis: DPDP uncertainty leads to inaction.
✗ Operators seen as competitors: cities withhold bus stop locations.
✗ Official churn: frequent transfers erase institutional memory.

Data ownership and legal framework

✓ Transit data is a public good: taxpayer-funded data should be taxpayer-owned — not government or vendor-owned.

✓ Namma Yatri model: a private entity opened its data for trust, enabling research in Chennai and Bangalore.

✓ Personal data protected: DPDP Act (mandatory 2027) needs consent for PII.

✓ Geospatial exception: National Geospatial Policy (2022) mandates publicly-funded geospatial data be public.

✗ Non-personal data unregulated: no ownership concept — a "free for all" with no sharing mandate.

Scaling challenges

India's diversityEvery state/city is different — reaching each SDU takes far longer.
No central mandateUnlike roads/flyovers, open data has no enforcement as law/rule.
Capacity gapsAgencies can't code or maintain data; each reinvents the wheel.
Broken procurementTendering blocks innovation; marketplace-based procurement is needed.

National level

→ If MoHUA sets standards, everyone follows — fastest path to scale.

→ Policy → law: move from guidance to enforceable acts/rules.

→ ONDC model: open network working — 9+ metros joining.

Institutional

→ Capacity programs for crew, bus, depot management data.

→ Handhold agencies — prove value via use cases.

→ Tender specs: mandatory clauses for data ownership.

Technical

→ India-specific operational data standards.

→ Software escrow: UK-style model for continuity.

→ Open-source community: shared base for vendors.

Data quality and standards

✗ Route ID problems: 37% of trips don't follow route IDs.

✗ AIS-140 GPS standards: present at policy level, but implementation varies.

✗ GTFS insufficient: needs an operational data layer (crew, depot, fleet) beneath it.

✗ Metrics needed: the platform should publish quality metrics alongside the data.

Open questions

? Revenue sharing: how do we compensate individuals whose aggregated data creates value?
? Joint ownership: should data individuals generate on public systems be jointly owned with the operator?
? Vendor continuity: how do we balance open systems with vendor models when interoperability erodes lock-in?

What we're taking forward

1. Research consortium — Prof. Gita, Prof. Pravesh and Prof. Inder to build India-specific operational data standards.
2. Capacity-building curriculum — Train transit agencies on data-coding standards and maintenance.
3. Standard tender template — Mandatory tender clauses ensuring data ownership and openness for all SDU procurements.
4. Data-quality metrics — Record and publish quality metrics on the Delhi Transport Stack platform.

What's on Transport Stack

Platform features

Multimodal coverageBuses, metros and shared mobility — all standardized in one place. Open-source code baseJourney planner, ETA services, bus-bunching detection — all public repos.
Low entry barrierTransparent ecosystem designed to cut the cost of entry for developers and researchers. OTD migration in progressOlder Open Transit Data platform being deprecated; all data moving to Transport Stack.

Representative datasets on the platform

Bus static data (GTFS)Routes, stops, schedules and trip definitions for Delhi's bus network. Bus real-time data (AVLS)Live vehicle positions from on-board GPS units.
Bus ETA & derived feedsArrival predictions and bus-bunching detection from raw AVLS. Metro dataMetro routes, stations and schedules in the same standardized format.
Intermediate Public TransportShared-mobility data around metro stations — autos and e-rickshaws. Journey planner APIsPublic API endpoints for multimodal trip planning.
Coming soon: ticketing & ridership. Delhi's ticketing data exists but sits in a disguised internal system; transport-department approval is pending before it can be released.
